Reading setpoint confirmation…

A setpoint can read back perfectly and still be ignored. Solis, Sungrow and Chint ignore an active-power setpoint until a separate enable register holds the value their manual specifies. The setpoint register still accepts the write and still echoes it back, so the readback above matches while the inverter keeps generating at full output. An enable register that is not confirmed by a read is therefore a different fault from a setpoint that read back wrong, and it has a different remedy. Reading the enable-register state…

Lab validation

Declare or revoke a lab simulator target

Locked
Declaring a lab target changes what the controller may command. It grants command authority through a profile that has not been qualified on physical equipment. It disables automatic control. The firmware does this deliberately whenever a profile assignment changes. The controller must be restarted before the returned write permission takes effect. While any commanded inverter is a declared simulator, commissioning can only ever report lab_simulator_only, never production.

Declarations currently held by the controller are listed below, read from the controller itself rather than from what this browser last sent. A slot whose declaration cannot be read is reported as not a lab target.

An unconfirmed enable register is not a setpoint fault. A setpoint that read back wrong is reported as a setpoint fault. An enable register that is not confirmed produces no setpoint fault at all: the setpoint is accepted, echoed back and ignored, so it reads as confirmed while the inverter runs unlimited. Unconfirmed is transient and the controller keeps retrying it.
